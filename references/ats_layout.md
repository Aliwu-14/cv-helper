# ATS 排版硬约束

本文档规定简历导出与排版时必须遵守的机器可读约束。所有结论综合 Workday / Greenhouse / iCIMS / Bullhorn / Lever 等主流 ATS 与 2026 年最新简历优化指南。

## 1. ATS 实际是怎么读简历的

- ATS 把 PDF/DOCX 强制转成纯文本流，按行从左到右、从上到下顺序扫描；
- 视觉装饰在转换时被完全丢弃——加粗、斜体、颜色、图标、纹理都对机器无效；
- 系统对文本块做结构化抽取，预设字段：姓名、联系方式、教育、经历、技能、证书、项目；
- 每个字段通过"自身 GPS 坐标"匹配：模块标题 + 时间 + 公司 + 动作；
- 如果某段在文本流里没有被识别为标准字段，就被丢弃（不进候选人画像）。

## 2. 硬性结构规则

| 规则 | 必须 | 禁止 |
|------|------|------|
| 布局 | 单栏、左对齐 | 多栏 / 双栏 / 侧栏 |
| 字体 | 标准字体（思源黑体 / 苹方 / Arial / Calibri / Times New Roman） | 艺术字 / 非标准嵌入字体 |
| 字号 | 正文 10–11pt，标题 12–14pt | 全文同号 / < 9pt |
| 段落标题 | 标准中英文（「教育背景」「Education」「工作经历」「Work Experience」「Skills」「技能」之类） | 创意标题（「我的探索之旅」） |
| 项目符号 | 简单 `•` 或 `-` | 星形、勾选、箭头、表情 |
| 日期格式 | `YYYY.MM – YYYY.MM` 或 `Mon YYYY – Mon YYYY`，全篇统一 | 中英混排、`2023.3-2024.6` 与 `Mar 2023 – Jun 2024` 共存 |
| 联系方式 | 放正文最上方，单字符 + 关键字 | 放页眉 / 页脚 / 文本框 / 图标 |

## 3. 必须删除的元素

- 表格（特别是 ATS 不能解析的复杂表格）；
- 文本框 / 文本框标题 / 文本框链接；
- 图标、图形、徽标、二维码、照片；
- 嵌入式图表、SmartArt、PPT 截图；
- 多栏 / 左右分栏 / 卡片区；
- 艺术字、阴影、手写体；
- 加密文档、扫描件 PDF；
- 仅装饰用的项目符号（⭐ ✅ ⚡）；
- 技能评分条 / 气泡图；
- 居中姓名 + Logo 排版。

## 4. 关键词策略

- 关键词数量自检：JD 中重复出现或出现在"必备条件 / 加分项"中的名词与动词，共计 15–25 个自然出现；
- 缩写与全称同时出现，例如 `SEO / 搜索引擎优化`；
- 关键词在个人总结中先 1–2 个；
- 技能模块按分组列出 10–15 个核心关键词；
- 经历描述中以自然句嵌入关键词，而不是孤立写 `Python, SQL, Tableau`；
- 把 JD 复制到词云工具或简单手动高亮，找出高频词，复盘简历是否覆盖。

## 5. 量化与 STAR 压缩

每条 bullet 应包含至少一项量化锚点；如果实在没有绝对数字，按下表降级替代：

| 类型 | 示例 |
|------|------|
| 比例变化 | 接口响应时间从 1.2s 降至 0.3s，跳出率下降 22% |
| 覆盖率 | 测试覆盖率从 41% 提升至 87% |
| 采纳情况 | 提案被纳入 Q3 路线图；流程改进设为团队标准模板 |
| 覆盖规模 | 覆盖华北、华东共 8 城；协调 6 个部门 22 名执行成员 |
| 阶段进展 | 完成用户调研阶段，深度访谈 28 名核心用户 |
| 周期 / 频率 | 周度产出市场简报，连续 12 期 |

STAR 思考过程压缩到 bullet 后只剩：动词 + 对象 + 量化 + 方法 + 价值。面试或求职信里再展开完整 STAR。

## 6. 数字化导出与自检

| 步骤 | 操作 |
|------|------|
| 1 | 用可编辑工具（Word / Notion / 超级简历）排版，导出 PDF； |
| 2 | 在 PDF 阅读器里尝试复制一段文字；无法复制 → 替换为文本式 PDF； |
| 3 | 把复制出的纯文本打开，看段落标题、时间顺序、bullet 是否正确； |
| 4 | 在 ATS 模拟器（Jobscan / Resume Worded / 智灵 AI）跑 75%+； |
| 5 | 用 `scripts/validate_section.py` 自检每个模块字符区间与禁止模式。 |

## 7. 中英文混合简历

- 中英文简历标题分开两行；
- 同一份简历中不要双语夹杂（"Work Experience 工作经历"只保留一种语言）；
- 英文项目首字大写、避免双空格；
- 缩写规范：`SQL`、`CRM`、`OKR`、`KPI`、`RAG`、`CoT`、`PMO`、`WBS`、`RAID` 等行业缩写保留全大写；混合词（`A/B Testing`、`Top-down/Bottom-up`）按行业惯用形式书写。

## 8. 一页 vs 两页

| 资历 | 推荐页数 |
|------|----------|
| 应届 / 0–3 年经验 | 1 页 |
| 3–7 年经验 | 1–2 页，看内容密度 |
| 7 年以上 | ≤ 2 页 |
| 学术 / 资深岗位 | ≤ 2 页 |
| 第 2 页推荐空白多少 | ≥ 1/3，避免半页 |

**经验法则**：如果出现第 2 页但只填到 1/3，需要做"砍掉最弱的那条"的取舍，而不是缩小字号或留白挤进去。
