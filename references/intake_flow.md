# 多轮引导流程：状态机与提问脚本

本文件是 SKILL.md "执行流程"的具体实施蓝本。所有 Agent 在加载 `cv-helper` Skill 后必须按本状态机逐项提问，**一次只问一项**，每收到答复后立刻进入下一项，**不要把多个问题合并到一条消息里**。

## 总体流程图

```
加载 Skill
   ↓
开场白（一次输出）
   ↓
[阶段 1 基本信息] ─→ 8 项必填 + 1 项可选
   ↓
[阶段 2 求职方向] ─→ 4 项
   ↓
[阶段 3 目标公司与岗位] ─→ 3–4 项
   ↓
[阶段 4 突出亮点] ─→ 3–5 项
   ↓
[阶段 5 履历内容] ─→ 4 个子模块（教育 / 经历 / 技能 / 奖项）
   ↓
[阶段 6 生成与校验] ─→ 研究 + 生成 + 校验
   ↓
[阶段 7 迭代] ─→ 反复直到用户满意
```

每个阶段独立可中断、可重入。用户可以随时说"我有 PDF 简历"跳到阶段 5，或说"我想改公司"回到阶段 3。

## 开场白模板

第一次回复**必须**只输出开场白，不夹杂任何提问。开场白固定包含：流程说明 + 预计轮次 + 是否需要用户提供简历 + 第一个问题。

### 模板 A：用户已指明公司 / 岗位

> 欢迎使用 **cv-helper** 简历助手。下面我会按 6 个步骤带你完成一份针对 **[公司名 / 岗位名]** 的中文简历：
> 1. **基本信息**（姓名、电话、邮箱、城市、学历，约 6 项）
> 2. **求职方向**（行业 / 职能 / 期望城市 / 工作形式）
> 3. **目标公司与岗位确认**（你已给了，我会再确认一遍是否完整）
> 4. **希望突出的亮点**（3–5 项你最想让 HR 注意的项目 / 能力 / 数据）
> 5. **履历内容**（教育 / 经历 / 技能 / 奖项，按 STAR 简述）
> 6. **生成与 ATS 校验**
>
> 每一步我都会一项一项问你，回答后立刻进入下一步；全部收集完后我会研究公司 + 生成简历 + 跑 ATS 校验，预计 1–2 分钟。
>
> 你也可以随时贴一份现成简历原文 / PDF，我跳过第 5 步。
>
> 准备好了吗？我们从 **基本信息** 开始。先告诉我你的 **姓名**？

### 模板 B：用户未指明公司 / 岗位

> 欢迎使用 **cv-helper** 简历助手。下面我会按 6 个步骤带你完成一份中文简历：
> 1. **基本信息**（姓名、电话、邮箱、城市、学历）
> 2. **求职方向**（行业 / 职能 / 期望城市 / 工作形式）
> 3. **目标公司与岗位**（公司名 / 岗位名 / JD；如果你还没定，我会推荐 2–3 个候选）
> 4. **希望突出的亮点**（3–5 项）
> 5. **履历内容**（教育 / 经历 / 技能 / 奖项）
> 6. **生成与 ATS 校验**
>
> 每一步我都会一项一项问你，回答后立刻进入下一步。
>
> 你也可以随时贴一份现成简历原文 / PDF，我跳过第 5 步。
>
> 准备好了吗？我们从 **基本信息** 开始。先告诉我你的 **姓名**？

## 阶段 1：基本信息

| 顺序 | 字段 | 必填 | 提问文案 |
|------|------|------|----------|
| 1 | 姓名 | 是 | "请告诉我你的姓名？" |
| 2 | 联系电话 | 是 | "联系电话（手机号）？" |
| 3 | 电子邮箱 | 是 | "电子邮箱？例如 your.name@example.com" |
| 4 | 所在城市 | 是 | "目前所在城市？" |
| 5 | LinkedIn / GitHub / 作品集 | 否 | "是否有 LinkedIn / GitHub / 个人作品集链接？有的话一并告诉我，没有可跳过。" |
| 6 | 最高学历 | 是 | "最高学历？例如：本科 / 硕士 / 博士 / MBA / 在读硕士" |
| 7 | 学校 + 专业 + 毕业时间 | 是 | "学校 + 专业 + 毕业时间（YYYY.MM）？例如：北京邮电大学 金融学 2025.06" |
| 8 | 工作年限 | 是 | "毕业到现在的总工作 / 实习年限？例如：2 年全职 + 1 段 6 个月实习" |

### 跳过规则

- 用户主动说"先跳过姓名""我以后补" → 接受占位符 `{{姓名}}`，但不阻塞阶段推进。
- 用户拒绝回答某项（如 LinkedIn）→ 标记为"无"，不重复追问。

### 阶段 1 完成后的过渡语

> 基本信息收到 ✅。我们进入 **求职方向**。先告诉我 **目标行业**？例如：互联网、金融科技、快消、制造业、教育、医疗、国企、公务员……

---

## 阶段 2：求职方向

| 顺序 | 字段 | 必填 | 提问文案 |
|------|------|------|----------|
| 1 | 目标行业 | 是 | "目标行业？例如：互联网、金融科技、快消、制造业、教育、医疗、国企、公务员" |
| 2 | 目标职能 | 是 | "目标职能？例如：产品经理、运营、数据分析、算法、研发、设计、市场营销、投资、战略" |
| 3 | 期望城市 | 是 | "期望城市？（可与所在城市不同）" |
| 4 | 工作形式 | 是 | "工作形式？全职 / 实习 / 兼职 / 远程" |

### 阶段 2 完成后的过渡语

> 求职方向收到 ✅。我们进入 **目标公司与岗位**。

---

## 阶段 3：目标公司与岗位

| 顺序 | 字段 | 必填 | 提问文案 |
|------|------|------|----------|
| 1 | 公司名 | 是 | "要投递的公司名？（多个用逗号分隔；还没定就说'还没定'）" |
| 2 | 岗位名 | 是 | "目标岗位？例如：产品经理、数据分析师" |
| 3 | JD 链接或文本 | 是 | "有 JD 链接或粘贴文本吗？贴过来即可。" |
| 4 | 投递状态 | 否 | "这家公司你已经申请 / 在面试 / 还是计划申请？" |

### 当用户说"还没定公司"时

不要替用户拍板。改成：

> 收到。还没定公司是正常的。我先根据你的方向（行业 + 职能）给你 **2–3 个候选公司**（按规模 / 业务 / 匹配度选），你确认或换一个：
>
> - **公司 A** — [一句话说明业务 + 为什么匹配]
> - **公司 B** — [一句话说明业务 + 为什么匹配]
> - **公司 C** — [一句话说明业务 + 为什么匹配]
>
> 哪个合适？或者你心里已经有方向，告诉我也行。

### 阶段 3 完成后的过渡语

> 目标公司与岗位收到 ✅。我们进入 **突出亮点**。

---

## 阶段 4：希望突出的亮点

这一步**必问**，且**至少 3 条**。

### 提问文案

> 在简历里你最希望 HR 注意到的 **3–5 项**亮点是什么？比如某段经历、某项目、某数据、某证书、某技能。可以是：
>
> - "我在 XX 项目把转化率从 12% 提到 19%"
> - "我熟练 SQL + Python，能独立做完整指标体系"
> - "我拿过 CFA Level 2 / 计算机竞赛一等奖"
>
> 至少给 3 条，最多 5 条。这些亮点会被自然融入到顶部四行总结与对应经历的 bullet 里，但**不会在总结里直接复述项目名 / 公司名 / 比赛名**。

### 收到少于 3 条时

> 你只给了 [N] 条。我需要至少 3 条才会让简历有差异化。可以再加 1–2 条吗？或者你描述得详细一点，我把一段经历拆成 2 条也行。

### 收到多于 5 条时

> 你给了 [N] 条亮点。我建议最多取 3–5 条最相关的；多余的可以放到"技能"或"经历"模块。你想保留哪几条？

### 阶段 4 完成后的过渡语

> 亮点收到 ✅。我们进入 **履历内容**。我会分教育、经历、技能、奖项四个子模块问你，每模块一次性问完。

---

## 阶段 5：履历内容

### 子模块 5a：教育补充

> 你刚才已给过学校 + 专业 + 毕业时间。还有什么想加进"教育背景"？可选：
> - **高 GPA**（≥ 3.5/4.0 或 ≥ 85/100）+ 排名（如 GPA 3.8/4.0，前 5%）
> - **相关课程 2–4 门**（如 机器学习、计量经济学、高级财务管理）
> - **学术荣誉**（如 国家奖学金、学术竞赛获奖）
> - **交换经历 / 双学位**（如 香港中文大学交换 1 学期）
> - **毕业论文 / 研究方向**（如 机器学习在信用评分中的应用）
>
> 一次回完即可，没有就告诉我"无"。

### 子模块 5b：经历补充

> 接下来是 **经历模块**，按时间倒序，每段经历用 3–5 句话告诉我：
> - 在哪个公司 / 项目
> - 什么角色
> - 什么时间段
> - 做了什么动作
> - 用什么方法工具
> - 量化结果如何
>
> 如果你有一段完整简历原文（PDF / Word / 文字），可以直接贴过来，我帮你拆 STAR bullet。逐段粘贴也行。

### 当用户贴出原文 / PDF

立即跳过子模块 5b–5d 的提问，进入 **解析** 流程：

> 收到原文，我会按 STAR 提取关键经历，预计 30 秒。先帮你拆出 **5–8 段候选经历**，然后给你看一遍，纠正错漏。

候选经历列表展示格式：

```
1. 公司A | 岗位 | 时间
   → bullet 1: …
   → bullet 2: …
2. 公司B | 岗位 | 时间
   → bullet 1: …
```

### 子模块 5c：技能

> 列出你会的 **工具 / 编程语言 / 方法 / 语言证书**，按熟练度告诉我即可：
> - 熟练（能独立负责 / 教别人）
> - 熟悉（能独立完成日常任务）
> - 能够应用（在指导下能完成）
> - 了解边界（知道原理与适用场景）
>
> 一次回完。

### 子模块 5d：奖项与证书

> 列出你拿过的 **奖项 / 证书 / 资格考试**，每条按格式：
> - 年份（如 2024）
> - 奖项名（如 CFA Level 2 通过）
> - 授予方（如 CFA Institute）
> - 量化信息（如 全球 Top 35% / 分数 580）
>
> 没有就告诉我"无"。

### 阶段 5 完成后的过渡语

> 履历收到 ✅。我现在开始研究公司 + 生成简历，**预计 1–2 分钟**。

---

## 阶段 6：生成与校验

### 6.1 公开信息研究

- 优先访问：官方招聘页、官网业务页、官网新闻 / 投资者资料。
- 备用：可靠招聘平台（LinkedIn / 拉勾 / BOSS）、权威行业媒体。
- 整理：3–5 个高优先级关键词与术语，保留 URL 与发布日期（内部使用）。

### 6.2 构建证据矩阵

把阶段 4 亮点 + 阶段 5 履历映射到 SKILL.md "输出契约" 的六段模块。每个候选 bullet 必须有 1 个事实锚点（不可编造）。

### 6.3 输出简历正文

按六段模块输出（个人总结 / 基本信息 / 教育 / 经历 / 技能 / 奖项），附 `## 排版与导出指引`。

### 6.4 跑校验

```bash
python3 scripts/validate_output.py <resume.txt>      # 顶部四行
python3 scripts/validate_section.py --mode experience <resume.txt>
python3 scripts/validate_section.py --mode skills <resume.txt>
python3 scripts/validate_section.py --mode education <resume.txt>
python3 scripts/validate_section.py --mode awards <resume.txt>
```

校验失败必须重写或压缩，**直到通过为止**。

### 6.5 主体检查

把公司名 / 团队名 / JD 文本全部遮住；整份简历应仍描述候选人本身而非"为何适合该岗位"。**若不通过，强行重写**。

### 6.6 输出规则

首次输出**只输出**简历正文 + 排版规范指引。**不要解释为何生成**。用户追问时再给关键词对应表与证据映射。

---

## 阶段 7：迭代

生成后**必须**给出选择菜单：

> 简历已生成 ✅。你可以做以下选择：
> 1. **没问题** — 走 [references/templates.md](references/templates.md) 导出为 LaTeX / Marp / HTML / PDF
> 2. **调整某段经历** — 指出哪一段、哪条 bullet
> 3. **调整四行总结** — 哪一条
> 4. **改成英文版** — 走 [scripts/validate_output_en.py](scripts/validate_output_en.py) 流程
> 5. **加 / 减亮点** — 哪些亮点
> 6. **换公司 / 岗位** — 重新走阶段 3

每次迭代后**重新跑校验**。

## 用户中途介入的处理规则

| 用户输入 | 处理 |
|----------|------|
| "我有 PDF 简历" | 跳到阶段 5b，让用户贴原文 / 上传文件 |
| "跳过基本信息" | 接受占位符 `{{}}`，不阻塞 |
| "我改主意了" | 回到对应阶段 |
| "直接给我简历模板" | 拒绝，重定向到开场白 + 阶段 1 |
| "帮我也写英文版" | 阶段 7 选项 4；切换到英文校验器 |
| "我没时间回答这么多" | 跳到阶段 5b，要求贴一段现有简历或履历要点；其他信息用 `{{占位符}}` |
| "能不能给我看看问题清单" | 一次性输出阶段 1–5 所有问题，让用户离线填完再贴回来 |
